# Chase Bianchi

Personal portfolio for [www.chasebianchi.com](https://www.chasebianchi.com): a homepage with the current role, four case studies, the career path, and contact, plus an HTML resume that is also the source of the PDF.

## Development

```bash
npm ci
npm run dev               # Vite development server, port 3000
npm run build             # Multi-page production build in build/
npm run preview           # Serve the production build, port 4173
npm test                  # Vitest content, link, and interaction checks
npm run test:e2e          # Playwright desktop/mobile journeys
npm run build:resume-pdf  # Rebuild, then render /resume/ to the PDF
```

The site is static HTML bundled by Vite, with one stylesheet and a small script. All content is available without JavaScript. Vercel serves the multi-page build.

## Editing the site

- `index.html`: homepage (hero and current role, work list, career path, contact).
- `work/*/index.html`: four case studies, each with its own title, description, and canonical URL.
- `resume/index.html`: the resume. After editing it, run `npm run build:resume-pdf` to regenerate `public/assets/chase-bianchi-resume.pdf` (must stay at two pages or fewer) and commit the PDF.
- `src/run.js`: the homepage hero. A simulated delivery run in which the visitor assigns a ticket and approves at both gates. Ticket text, plans, and answers live in `TICKETS` at the top of the file; keep answers at 60 words or fewer.
- `src/lab.js`: the decision lab. A set of poker decisions to browse, one per distinct situation (flush draw, pair plus flush draw, and so on), always with the opponent ahead; each is played once, then simulated 1,000 times and charted.
- `src/poker.js`: the hand evaluator the lab uses to work out exact odds. `src/lab-data.js`: the scenarios, generated by `node scripts/generate-lab-scenarios.mjs` (seeded; edit `SITUATIONS` in that script and rerun, do not edit the data by hand).
- `src/site.js`: mobile navigation, scroll reveals, email drafting/copying, and the case-study walkthrough.
- `src/styles/site.css`: the design system. Light or dark follows the visitor's browser/system setting until they use the header toggle, which overrides it and is remembered. `src/styles/resume.css`: resume sheet and print rules.
- `public/assets/`: self-hosted fonts (Instrument Serif, Manrope, IBM Plex Mono; all OFL), favicon, and the resume PDF.

The header, footer, and contact block are repeated in each HTML file; change them in all six pages. `tests/unit/site.test.js` checks that navigation and footer links stay consistent.

The footer labels [personal GitHub](https://github.com/ChaseBianchi) and [Slalom work GitHub](https://github.com/ChaseBianchiSlalom) separately. Use personal GitHub credentials for this repository.

The contact form opens a draft in the visitor's email application. It does not send or store messages and requires no service credentials. The delivery run, walkthrough, and decision lab all run in the browser; none of them call agents or models, and the page says so. The lab's card draws and 1,000-hand results are genuinely simulated; the delivery run's log is scripted.
